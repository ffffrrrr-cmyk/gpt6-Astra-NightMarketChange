# FR-0003 规则与决策

## 依据与变更

用户于当前开发会话明确允许缺少通用规范时按现有材料实施，并要求“使用真实人民币面额，重新调整规则”。以此作为对原PRD固定三枚硬币条款的变更依据。原PRD保留用于追溯，游戏以本文规则版本 `rmb-1` 执行。

- 面额：1元硬币、5元纸币、10元纸币，均为人民币实际面额。画面为原创面额示意图，不复刻人民币设计。
- 每客支付恰好10元，商品价格3元，应找7元。
- 允许两种找法：5元纸币+两枚1元硬币，或七枚1元硬币。取消固定三枚条件，以便真实币值下存在两种有意义的资源选择。
- 每关8位顾客必须全部连续完成；成功计数初始0，失败终止本次流程。
- 开局设定为已经营业过一段时间。首关前客留存为5元纸币一张、1元硬币两枚，共7元。这是关卡叙事初态，不伪装成玩家实际执行过的交易或rollout记录。其他关卡有公开的不同前客留存。
- 当前顾客付款在成功找零前不可用。提交时从旧库存扣7元，再将该顾客10元入账，此时他成为后客的前客。不允许先借其付款给其找零。
- 10元纸币进入收入格，计入总现金，但无法用于找7元。零钱盘容量只计算1元硬币及5元纸币的张枚数；容量定义在关前和游戏中公开。没有兑换或被动补钱。
- 每次成功确认完成一客并推进一个经营周期；选择、拖拽排序、查看详情、选钱、取消草稿不推进。
- 玩家选定客人并确认即承诺接单。若旧库存完全无法凑7元，提交造成“零钱不足却接单”；若旧库存存在合法组合，但草稿选错金额/数量，则拒绝而不改变状态。前置关系不满足、容量超出、约定时间窗口不满足亦拒绝，不偷偷扣钱。
- 每关的顾客前置关系、可服务回合窗口及零钱盘容量全部公开；前期教学后再组合。顾客只能排序，不能取消已完成订单或刷收益。
- 成功服务后若库存不足，保留风险状态让玩家看到原因并可触发接单失败。若尚能找零但所有剩余顺序均已无法完成，提交时报告目标不可达。解算器证明可达性，不用随机推断。
- 失败优先于胜利，终局仅一次。达到8客成功时胜利。重复commandId无副作用。所有金额用整数元。
- 效率指标为本关交付的现金张枚总数；越少越高效。安全性指标为过程中保留的可找零组合数及最少1元硬币余量。计分仅用于通关优化，所有合格解同为8客。

## 守恒与例子

总现金 = 1元枚数 + 5×5元张数 + 10×10元张数。每次成功交易净增3元；没有可用零钱并不等于没有现金。

例：旧库存5+1+1，顾客付款为十枚1元。必须先用旧库存5+1+1完成找零，随后收到十枚1元。新库存10元，下一客可以用七枚1元，不能将当前客的10枚硬币提前挪用。

12关的具体初态、付款、顺序关系、窗口和容量由关卡配置集中定义；求解轨迹与验证报告随实现生成。

首关专属失败轨迹：从初态先服务周伯，递出5+1+1后收到10元整钞，库存变为0/0/1；此时再承诺任一合规订单即“零钱不足却接单”。失败不会借用当前客人的钱，也不会再次扣费。重试返回2/1/0。

## 实施顺序

1. 建立纯规则内核及一个可解单元，验证守恒、失败、去重和8客通关。
2. 完成12个有结构差异的手工单元，用求解器验证每关胜败及指定双解。
3. 实现Canvas夜市、输入、流程、声音、存档、设置和教学。
4. 自动检查浏览器与离线构建，交付运行入口和用户试玩步骤；人工画面/手感与5人首次测试单独待测。
