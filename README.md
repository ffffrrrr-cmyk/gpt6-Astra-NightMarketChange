# 夜市找零 · FR-0003

一款可以离线游玩的2D回合经营游戏。用1元硬币、5元和10元纸币，安排八位客人的服务顺序：每客收10元，先找7元，再将他的付款留给下一位。12个手工夜晚依次引入面额资源、两种找法、先后约定、服务窗口和零钱盘容量。

## 直接游玩

双击项目根目录 `Launch.cmd`，或用Chrome/Edge打开 `dist/index.html`。成品代码、样式、美术与声音全部内嵌，运行不需要Node、不需要联网，也没有外部字体、账号或服务端。

本机绝对入口：`E:/Sale Gpt6/游戏采购开工包_20261105/0003-web-夜市找零/dist/index.html`。

存档保存在当前浏览器及当前页面来源。切换浏览器、改变文件路径或从文件入口切换到HTTP入口，可能出现独立的存档空间。浏览器禁止文件页存储时会提示仅在内存保留；此时可选择本机HTTP方式运行以便获得稳定来源：

```powershell
npm start
```

随后访问 `http://127.0.0.1:43103`。端口占用时程序明确报错，不会关闭其他进程；可设置项目专属环境变量 `NIGHT_MARKET_PORT` 后启动。没有任何远端服务器。关闭此服务终端即可停止。

## 操作与规则

- 左键选候客卡，查看付款和公开约定；拖动卡片调整候选顺序，随后点选要服务的客人。
- 点钱盘选择1元硬币或5元纸币；点已选的钱将其收回。右键或“清空”取消草稿。
- 回车或“确认找零”提交一笔交易；每次成功提交推进一回合。Esc暂停，窗口失焦也会暂停。
- 找7元有两种组合：5+1+1，或者七枚1元。10元整钞留在收入格，不能用于找7元。
- 当前客人的10元必须等成功找零后才入账。不能提前拿他的付款给他自己找零。
- 钱盘容量只计1元硬币与5元纸币的张枚数。公开前置关系和服务窗口需同时满足。
- 错误选币会被拒绝，不扣款。已有零钱完全无法凑7元却确认接单会失败。已无法完成余下约定的局面会明确结算，不留下死局。
- 每夜连续服务8客通关。递出张枚数作为通关优化记录，越少越高效；重试恢复关前快照，不保留失败收益。

### 用户确认的需求调整

用户要求使用真实人民币面额并重新调整规则。因此原PRD的“三枚硬币”改为上述两种合法找法；首关7元为先前营业的留存，服务计数从0开始。详细口径及变更依据见 `Documentation/规则与决策.md`。通用执行规范缺失时，用户已明确允许按现有材料实施，缺失规范核对仍待补。

## 开发与复现

实际工具链：Windows x64，Node v24.19.0，npm 11.17.0，TypeScript 7.0.2，esbuild 0.28.2，Playwright CLI 0.1.23。依赖由 `package-lock.json` 锁定。开发工具联网安装和成品离线运行是两回事。

```powershell
npm ci --ignore-scripts
npm run typecheck
npm test
npm run validate
npm run build
npm start
```

`Build.ps1` 依次运行类型检查、规则/存档测试、全部关卡求解与构建；不隐式安装依赖。`npm run package` 固定源码文件哈希，生成交付清单、来源许可副本、离线包与源码包。具体状态以 `Validation/verification-report.md` 为准。

## 工程结构

| 路径 | 职责 |
| --- | --- |
| `src/core` | 纯规则、只读预览、原子命令、幂等、求解与事件重放 |

| `Validation` | 有效解、失败轨迹、自动检查记录和分项验收报告 |
| `Provenance` | 真实模型标识、会话来源索引与公开开发摘要 |
